# 🧠 Git — краткая и понятная шпаргалка

Этот файл — твоя личная памятка по Git.  
Цель: быстро вспомнить, **что делает каждая команда и зачем нужны ключи.**

---

## 📌 БАЗОВЫЕ ПОНЯТИЯ

**repository (repo)**  
Папка проекта + вся история изменений.

**commit**  
Снимок изменений с сообщением.

**branch (ветка)**  
Параллельная линия разработки.

**remote (origin)**  
Удалённый репозиторий (обычно GitHub).

**merge**  
Слияние одной ветки в другую.

---

# 🧭 НАВИГАЦИЯ И СТАТУС

### `git status`
Показывает:
- в какой ты ветке,
- какие файлы изменены,
- какие готовы к коммиту.

Пример:

On branch feat/login
Changes not staged for commit:
modified: apps/web/app/login/page.tsx


---

### `git branch`
Показать список веток.

---

### `git branch --show-current`
Показать текущую ветку.

---

# 🌿 РАБОТА С ВЕТКАМИ

### `git checkout -b <name>`
Создать **новую ветку** и сразу в неё перейти.

Пример:

git checkout -b feat/login-form


Разбор:
- `checkout` — переключиться
- `-b` — создать ветку перед переключением

---

### `git checkout main`
Переключиться на ветку `main`.

---

### `git branch -M main`
Переименовать текущую ветку в `main`.

Ключ `-M` означает:
> “force move” — принудительно переименовать ветку.

Обычно нужно, если было `master`, а ты хочешь `main`.

---

### `git merge <branch>`
Слить другую ветку в текущую.

Пример:

git checkout main
git merge feat/login-form


---

# 📁 ДОБАВЛЕНИЕ ФАЙЛОВ В КОММИТ

### `git add <file>`
Добавить конкретный файл в будущий коммит.

Пример:

git add apps/web/app/login/page.tsx


---

### `git add .`
Добавить **все изменённые файлы** в текущей папке.

`.` = “всё здесь”.

---

# 💾 КОММИТЫ

### `git commit -m "сообщение"`
Создать коммит с сообщением.

Пример хорошего стиля:

git commit -m "feat(web): add login form state"


Рекомендуемые префиксы:

| Префикс | Когда использовать |
|--------|-------------------|
| `feat:` | новая фича |
| `fix:` | исправление бага |
| `chore:` | техническая работа |
| `docs:` | документация |
| `refactor:` | изменение структуры без новой логики |

---

# 🌐 РАБОТА С GITHUB (REMOTE)

### `git remote add origin <URL>`
Добавить удалённый репозиторий (GitHub).

`origin` — стандартное имя для GitHub.

---

### `git push origin <branch>`
Отправить ветку на GitHub.

Пример:

git push origin feat/login-form


---

### `git push -u origin <branch>`
То же самое, но с важным бонусом.

Ключ `-u` (или `--set-upstream`) означает:
> “Свяжи мою локальную ветку с веткой на GitHub”.

После этого можно писать просто:

git push
git pull

без указания `origin` и названия ветки.

---

# ⬇️ ПОЛУЧЕНИЕ ИЗМЕНЕНИЙ

### `git pull`
Забрать изменения с GitHub в текущую ветку.

Обычно делаешь перед началом работы:

git checkout main
git pull

# 🔍 ЧАСТЫЕ ОШИБКИ И КАК ИХ ПОНЯТЬ

### “nothing to commit”
→ Ты ничего не добавил через `git add`.

---

### “Your branch is ahead of origin”
→ Ты сделал коммиты локально, но ещё не запушил:

git push


---

### “Your branch is behind origin”
→ На GitHub есть новые изменения — сделай:

git pull


---

# 🎯 КОРОТКАЯ ПАМЯТКА (1 взгляд)

| Команда | Что делает |
|--------|------------|
| `git status` | показывает состояние |
| `git checkout -b X` | создать ветку X |
| `git add .` | подготовить всё к коммиту |
| `git commit -m "..."` | сохранить изменения |
| `git push -u origin X` | отправить ветку X |
| `git pull` | забрать изменения |
| `git merge X` | слить ветку X в текущую |
